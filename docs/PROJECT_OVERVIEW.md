# Help Desk System

## 1. Overview

The Help Desk System is a web application for managing customer support requests.

The system will allow customers to submit and track support tickets, while support agents will be able to organize, manage, and resolve those requests.

The project will start as a small application and evolve progressively as new requirements and technical challenges are introduced.

The goal is to build a realistic software system that demonstrates practical software development skills rather than simply implementing a collection of technologies.

---

## 2. Problem

Organizations need a way to manage customer support requests in an organized and traceable way.

Without a dedicated system, support requests can become difficult to track. Important information can be lost, requests may not be assigned correctly, and there may be no clear history of how an issue was handled.

This project aims to provide a simple system for managing the complete lifecycle of a support ticket.

---

## 3. Target Users

The system will eventually support three main types of users.

### Customers

Customers use the system to:

* Submit support requests.
* Track their requests.
* View responses from support agents.
* Communicate with the support team.

### Support Agents

Support agents use the system to:

* View support requests.
* Manage assigned tickets.
* Communicate with customers.
* Update ticket status and priority.
* Resolve support requests.

### Administrators

Administrators manage the system itself.

They may eventually be responsible for:

* Managing users.
* Managing support agents.
* Managing ticket categories.
* Monitoring tickets.
* Managing system configuration.

---

## 4. Main Concepts

The central concept of the application is the **ticket**.

A ticket represents a support request submitted by a customer.

Tickets will eventually contain information such as:

* Title
* Description
* Customer
* Assigned support agent
* Status
* Priority
* Category
* Creation date
* Last update date
* Comments

## 6. Development Approach

The application will be developed incrementally.

The initial version will focus on the core ticket-management functionality.

Later versions will introduce additional capabilities such as:

1. Persistent data storage
2. Web interface
3. User accounts
4. Authentication
5. Authorization
6. Ticket assignment
7. Comments
8. Ticket categories
9. REST API
10. Automated testing
11. PostgreSQL
12. Docker
13. Continuous integration
14. Deployment

Each stage should build on the previous one.
